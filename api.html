Для разработчиков

API для приёма платежей и выплат

Простое REST API: счета, статусы операций и массовые выплаты. Ниже — ориентировочная схема эндпоинтов для будущего бэкенда (сейчас они не развёрнуты, см. README.md).

Аутентификация

Запросы подписываются секретным ключом бизнес-аккаунта и передаются в заголовке.

Authorization: Bearer sk_live_xxxxxxxxxxxxxxxx Content-Type: application/json

Ключи — тестовый (sk_test_) и боевой (sk_live_) — будут выдаваться в личном кабинете бизнес-аккаунта после верификации.

Базовый URL

Адрес API будет объявлен после запуска бэкенда.

Основные эндпоинты

Ориентир для бэкенда — полная версия появится в отдельной документации

Счета и платежи

POST/v1/invoices
GET/v1/invoices/:id
GET/v1/payments

Создание платёжной ссылки, проверка статуса оплаты, список операций.

Выплаты

POST/v1/payouts
POST/v1/payouts/batch
GET/v1/payouts/:id

Разовая выплата получателю или пакетная выплата списком (batch).

Кошелёк

GET/v1/balances
POST/v1/exchange

Баланс по валютам и внутренний обмен между ними.

Вебхуки

POSTваш URL ← payment.succeeded
POSTваш URL ← payout.completed

Уведомления о событиях отправляются POST-запросом на указанный вами URL.

Пример: создание счёта

Запрос

POST /v1/invoices { "amount": 1500, "currency": "RUB", "description": "Заказ #1042", "webhook_url": "https://shop.example/webhook" }

Ответ

{ "id": "inv_8f21", "status": "pending", "pay_url": "https://platimarket.example/pay/inv_8f21" }

На фронтенде этот запрос пока эмулирует API.createInvoice() из js/api.js — метод возвращает демо-ответ без реального сервера.

Нужен доступ к API?
